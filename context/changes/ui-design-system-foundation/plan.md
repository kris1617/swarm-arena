# Shared app shell and extended design tokens Implementation Plan

## Overview

Establish the minimal cross-cutting UI foundation M-3's design-direction work needs: install shadcn/ui's official `sidebar` primitive (the token system already anticipates it), build a small `AppShell` component wrapping authenticated pages, fix the app's still-default branding metadata, and demonstrate the new token discipline end-to-end on the login page.

## Current State Analysis

- `src/styles/globals.css` already defines a **complete** shadcn sidebar token set (`--sidebar`, `--sidebar-foreground`, `--sidebar-primary`, `--sidebar-accent`, `--sidebar-border`, `--sidebar-ring`, etc. — lines ~16-23 of the `@theme inline` block) and a full `--chart-1` through `--chart-5` set, plus `--radius-sm` through `--radius-4xl`. None of these are used anywhere yet — no `sidebar` component exists in `src/components/ui/` (only `button.tsx`, `input.tsx`, `switch.tsx`). This confirms the project's shadcn setup (`components.json`: style `radix-nova`, base color `neutral`, `lucide` icons) was scaffolded anticipating a sidebar-shell layout, never finished.
- `src/app/layout.tsx` (RootLayout) renders a global top bar for signed-in users — `<form>` wrapping a "Sign out" button — styled with literal hex/opacity values (`bg-[#2e026d]`, `bg-white/10`), not tokens. `metadata.title`/`description` are still the unmodified Create-T3-App scaffold defaults (`"Create T3 App"` / `"Generated by create-t3-app"`).
- `src/app/login/page.tsx` is similarly styled with literal values (`from-[#2e026d] to-[#15162c]`, `bg-white/10`) rather than the `from-primary to-background text-foreground` token pattern every other page in this app already uses (dashboard, simulation, runs pages) — login is the one page that never got migrated to tokens.
- `AGENTS.md`'s existing rule — "No literal colors or arbitrary Tailwind values in views — reference a token instead" — is already violated by both of the files above; this plan brings them into compliance as part of establishing the foundation, not as a separate concern.
- `components.json`'s `aliases.ui` is `~/components/ui` and `aliases.components` is `~/components` — the shadcn CLI, if run, writes new primitives to `src/components/ui/` and respects the existing `~/*` path alias already configured in `tsconfig.json`.

## Desired End State

Every authenticated page is wrapped in a shared `AppShell` — a sidebar navigation shell (using shadcn's official `sidebar` primitive, which already matches the project's existing design tokens) with links to the two routes that exist today (Dashboard, Simulation) — replacing the old ad hoc "Sign out" top bar. The login page is restyled with the project's existing token pattern (no literal hex values) and proper "Swarm Arena" branding. The app's `<title>`/meta description reflect "Swarm Arena", not the Create-T3-App scaffold defaults.

### Key Discoveries

- The sidebar token set already exists and is unused — this is "finish what the token setup already anticipated," not inventing new tokens.
- `RootLayout` is the one natural, already-shared mounting point for an app-wide shell — wiring `AppShell` in there is the actual minimal foundation move, not a separate "apply the shell everywhere" project; it is inherently cross-cutting because the mounting point already is.

## What We're NOT Doing

- No restyling of any individual page's own content (dashboard cards, the staging form, analysis charts, comparison tables) — that is S-16 through S-20's job, each building on top of this foundation.
- No nav links to pages that don't exist yet (Leaderboard, reference pages) — `AppShell`'s nav list only has Dashboard and Simulation for now; S-19/S-20 add their own entries when those pages ship.
- No dark/light theme toggle — this app has one theme (`:root` and `.dark` already hold identical values, by existing design); not revisited here.
- No change to `/` (the still-unmodified Create-T3-App scaffold root page) or to the sidebar's content on the login page itself — login is unauthenticated and does not get the sidebar (there is nothing to navigate to before signing in).
- No change to any tRPC procedure, database schema, or authentication logic.

## Implementation Approach

Two phases: first install the primitive and build `AppShell` plus fix the app-wide metadata (low-risk, additive); second, mount `AppShell` in `RootLayout` for authenticated sessions (the foundation's actual cross-cutting payoff) and restyle the login page to prove the token discipline end-to-end.

## Phase 1: Sidebar primitive, AppShell component, and branding metadata

### Overview

Add the shadcn `sidebar` primitive, build `AppShell`, and fix the app's title/description metadata.

### Changes Required:

#### 1. Install the sidebar primitive

**File**: `src/components/ui/sidebar.tsx` (and any hook/util file the shadcn CLI generates alongside it, e.g. `src/hooks/use-mobile.ts`) — generated, not hand-written

**Intent**: Run `npx shadcn@latest add sidebar` to install the official primitive into this project's existing component/token setup. This is additive — it writes new files, does not modify `globals.css`'s already-complete sidebar tokens (shadcn's installer detects existing tokens and skips re-adding them, but verify the diff after running).

**Contract**: No new contract — the shadcn CLI's own generated API (`Sidebar`, `SidebarProvider`, `SidebarInset`, `SidebarContent`, `SidebarMenu`, etc., per shadcn/ui's documented sidebar component).

#### 2. `AppShell` component

**File**: `src/components/app-shell.tsx` (new file)

**Intent**: A client or server component (match whatever the generated `sidebar.tsx` primitive requires — check its own `"use client"` boundary) wrapping its `children` in `SidebarProvider` + `Sidebar` + `SidebarInset`, with a nav list of exactly two items today: "Dashboard" (`/dashboard`) and "Simulation" (`/simulation`), active-route highlighting via `usePathname()`, and a "Sign out" action (replacing `layout.tsx`'s current inline sign-out `<form>`) placed in the sidebar's footer area rather than a separate top bar.

**Contract**: `export function AppShell({ children }: { children: React.ReactNode })`. Not yet mounted anywhere in this phase — Phase 2 wires it into `layout.tsx`.

#### 3. Branding metadata

**File**: `src/app/layout.tsx`

**Intent**: Replace the `metadata` export's `title`/`description` (still `"Create T3 App"` / `"Generated by create-t3-app"`) with "Swarm Arena"-appropriate values.

**Contract**: `export const metadata: Metadata = { title: "Swarm Arena", description: "<one sentence matching the PRD's Vision>", icons: [...] }` — `icons` unchanged.

### Success Criteria:

#### Automated Verification:

- Type checking passes: `npm run typecheck`
- Linting passes: `npm run check`
- Full suite still passes: `npm test`

#### Manual Verification:

- (none for this phase — `AppShell` isn't mounted anywhere yet; nothing user-visible to check beyond the browser tab's title, covered in Phase 2's manual verification instead)

## Phase 2: Mount AppShell and restyle the login page

### Overview

Wire `AppShell` into `RootLayout` for authenticated sessions, and restyle the login page onto the existing token pattern — the end-to-end proof that F-06 works.

### Changes Required:

#### 1. Mount `AppShell` for authenticated sessions

**File**: `src/app/layout.tsx`

**Intent**: Replace the existing inline "Sign out" `<form>` block (rendered only when `session?.user` is truthy) with `<AppShell>{children}</AppShell>` for authenticated sessions; unauthenticated sessions (i.e. the login page) render `children` directly, unwrapped — no sidebar before sign-in.

**Contract**: `{session?.user ? <AppShell>{children}</AppShell> : children}` replaces the current conditional block; `signOut` moves from this file into `AppShell` (Phase 1, Change 2) as described above — remove the now-unused `signOut` import/usage from `layout.tsx` if `AppShell` fully owns it.

#### 2. Restyle the login page

**File**: `src/app/login/page.tsx`

**Intent**: Replace the literal `from-[#2e026d] to-[#15162c]` / `bg-white/10` classes with this app's existing token pattern (`from-primary to-background text-foreground`, matching dashboard/simulation/runs pages), and add "Swarm Arena" branding text (e.g. an `<h1>` or logo-style heading above "Sign in") so the page identifies the app, not just the action.

**Contract**: No prop/structural change — same `signIn("github", { redirectTo: "/dashboard" })` server action, same form — purely a className/content change.

### Success Criteria:

#### Automated Verification:

- Type checking passes: `npm run typecheck`
- Linting passes: `npm run check`
- Full suite still passes: `npm test`

#### Manual Verification:

- Visiting `/login` (signed out) shows the restyled page with "Swarm Arena" branding, token-based colors (no literal hex), and no sidebar
- Signing in and landing on `/dashboard` shows the new sidebar shell wrapping the existing dashboard content, with working Dashboard/Simulation nav links and a working sign-out action in the sidebar
- Navigating to `/simulation` keeps the same sidebar shell, with existing staging-form functionality unchanged
- The browser tab title reads "Swarm Arena", not "Create T3 App"
- No regression to any existing page's own content/functionality (dashboard's Running/Saved/Completed sections, the staging form's fields, run analysis/comparison pages) — only the surrounding chrome changed

**Implementation Note**: After completing this phase and all automated verification passes, pause here for manual confirmation from the human that the manual testing was successful before proceeding to the next phase.

## Testing Strategy

### Unit Tests:

- None planned — this is a presentational/layout change with no new business logic to unit-test. `AppShell`'s nav-highlighting logic is simple enough (`usePathname() === href`) that a dedicated test would mirror the implementation rather than protect it.

### Manual Testing Steps:

1. Sign out, visit `/login`, confirm branding and token-based styling.
2. Sign in, confirm the sidebar shell appears on `/dashboard` and `/simulation`, with working nav and sign-out.
3. Spot-check every other existing authenticated page (`/runs/[runId]`, `/runs/compare`) still renders correctly inside the new shell (not yet restyled internally — that's S-18 — but must not be broken by the new wrapper).

None — this is a layout/styling change, no new data fetching or computation.
